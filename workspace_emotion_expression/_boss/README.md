# Boss 指南

这是团队向你（用户）汇报的唯一出口。**你只需要看这个目录**，不用翻 `_shared/` 或各角色私有区。

## 目录

- `briefs/` — 团队写给你的**唯一工作输出**。其中 `YYYY-MM-DD-meeting-<topic>.md` 是组会小结，`YYYY-MM-DD-<stage>-summary.md` 是阶段总结。
- `decisions/` — 你拍板后的决策写在这里（你可以直接新建文件，或让团队代记录后你确认）。团队只读、执行。

你只需要阅读 `briefs/`，不用翻 `_shared/`、`_mailbox/` 或各角色私有区；这些目录是团队内部的事实、任务与问题记录。

## 小结阅读契约

每份会议小结或阶段总结都会包含：

1. **本次范围与证据边界**：明确哪些是已验证事实，哪些仍只是建议或待验证假设；没有实验时会直接说明“暂无实验结果”。
2. **最多 3 项进展**：只报告本次真正完成或已确认的工作。
3. **最多 3 项待确认事项**：每项都用同一结构说明“需要确认什么 → 可选路径与团队推荐 → 为什么现在需要确认 → 确认后的影响”。必要术语会附一句通俗解释。
4. **恰好 1 个风险**：只说明当前最会影响推进的问题。
5. **确认后的内部动作**：团队会如何回写决策、更新任务与关闭问题。

小结不会粘贴角色分工、原始内部问题或未整理的术语。战略范围、优先级、资源和许可等需要你拍板的事项会在小结中提出；技术探索问题由团队先在内部处理。

## 如何下指令

直接在对话里对团队说即可，例如：

- "全组讨论：我们应该用 diffusion 还是 flow matching 生成情绪表达？"
- "@critic 看看这个实验设计有什么漏洞"
- "进入 Ideation 阶段，主题是可解释的情绪表达生成"
- "让 builder 和 rigor 讨论一下这个方法的可行性"

团队会在每次**阶段推进或组会结束后**自动往 `briefs/` 写一份会议小结或阶段总结。你也可以随时要求“给我一份当前进展小结”。
